# Мой гараж

Telegram-бот для личного журнала обслуживания автомобиля. Можно завести несколько машин, записывать ТО, замену масла и фильтров, ремонт, симптомы и страховки. Карточка машины показывает последние замены, расходы по журналу, открытые проблемы и дату окончания страховки.

## Как пользоваться

1. Откройте `/start` и нажмите **Автомобиль**. Введите название или строку `Ласточка | Toyota Corolla | 2020 | 86 400`. Проверьте карточку и сохраните.
2. Нажмите **Запись** и отправьте сообщение. Например, `Вчера на 86 400 км заменил масло 5W-30 и фильтр за 7 500 ₽`. Бот покажет дату, пробег, стоимость, категорию и описание перед сохранением.
3. Для полиса укажите дату покупки, стоимость и срок действия. Например, `Купил ОСАГО 15.11.2026 за 9 800 ₽. Действует до 15.11.2027`.
4. Откройте историю и выберите нужный раздел. В карточке записи можно исправить данные, а у открытой проблемы отметить решение.

Команда `/garage` возвращает к списку машин.

## Карточки Telegram

- `CARD_STYLE=rich` включает Rich Messages с таблицами и раскрывающимися блоками Bot API 10.5. Бот вызывает `sendRichMessage` при первом показе, затем `editMessageText` с тем же `message_id`. [Журнал изменений Bot API](https://core.telegram.org/bots/api-changelog)
- `CARD_STYLE=widget` включает HTML-виджет для нового сообщения. Бот передаёт данные через `chat_data` и обновляет их методом `editMessageWidgetData`. При явном запрете со стороны Telegram бот открывает Rich Message. [Документация Telegram Widgets](https://core.telegram.org/bots/widgets)

## Данные

Бот отвечает только в личных чатах с идентификаторами из настроек. Владелец ведёт гараж. Преподаватель видит тот же список машин и историю, а изменение записей доступно владельцу. Номера автомобилей и VIN для работы не нужны. Журнал и черновики хранятся в D1, токен и разрешённые Telegram ID задаются через секреты Worker. `.gitignore` исключает локальные настройки, базы и выгрузки.

Разбор даты, пробега и типа записи работает в Worker. Если задан `OPENROUTER_API_KEY`, описание события передаётся OpenRouter для уточнения заголовка и категории. При пустом ключе обработки на внешнем сервисе нет.

## Локальная проверка

Нужен Node.js 22.13 или новее.

```sh
npm ci
npm test
npm run d1:local
npm run dev
```

`GET /health` возвращает `ok`. Тесты используют временную SQLite и имитацию ответов Telegram. Реальный чат проверяется после настройки нового бота.

## Настройка нового бота

1. Создайте бота через BotFather и базу командой `npx wrangler d1 create my-garage-bot`. Скопируйте `wrangler.toml` в `wrangler.production.toml` и запишите полученный `database_id` в этот локальный файл.
2. Выполните `npm run d1:remote -- --config wrangler.production.toml`, затем `npm run deploy -- --config wrangler.production.toml`.
3. Задайте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` и `OWNER_TELEGRAM_ID` через `npx wrangler secret put ИМЯ --config wrangler.production.toml`. Для просмотра преподавателем задайте `TEACHER_TELEGRAM_ID`. Случайный секрет вебхука можно получить командой `openssl rand -hex 32`.
4. Передайте те же токен бота и секрет вебхука через переменные окружения и запустите `npm run telegram:configure -- https://worker.example.com`. Скрипт установит меню, аватарку и вебхук. Откройте `/start` и проверьте добавление тестовой записи.

В проекте используется схема CarService с Telegram-вебхуком, D1 и опциональным разбором текста через OpenRouter.

## Первичное наполнение

`scripts/seed-garage.js` готовит три вымышленных автомобиля и по три записи о ТО, ремонте и ОСАГО для каждого. У каждой записи есть стоимость в рублях. Скрипт читает `OWNER_TELEGRAM_ID` из окружения и выводит SQL для выполнения в D1 после применения миграций. Выполните SQL из временного файла вне репозитория. Повторный запуск сохраняет существующие записи.
